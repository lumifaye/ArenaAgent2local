WHAT THE BRIDGE DOES

A narrow bridge.
A lot more control.

Arena Local connects Arena.ai's Bash tool to the folder you choose by default, offers optional read-only public web search and scraping, and can act as an MCP client for Roblox Studio's built-in local server. An optional, EXTREMELY DANGEROUS full-computer file mode can remove the workspace boundary after two local warnings. The conversation stays on Arena.ai; the desktop app handles local requests and permission decisions.

THE TOOLBOX

Small, explicit actions.

The bridge accepts thirteen named actions, including optional web search/scraping and the Roblox tool action (available only when its local integration is enabled)—not a general-purpose HTTP proxy. Each request has a unique ID, a declared action, and validated arguments.

▤

READ

List and inspect

List folders, read text files, and search matching lines inside the selected workspace. Binary content is blocked, text reads over 256 KB are refused, and search skips candidate files over 512 KB.

✎

WRITE

Propose file changes

Ask mode prepares a diff on the desktop. Approvals are tied to the exact reviewed file state, so a changed file needs a fresh review.

$_

COMMAND

Run a shell command

Ask mode shows the exact command before it runs. Commands use your OS account and are not sandboxed.

⌂

DEFAULT SCOPE

Choose one workspace

By default, file tools reject absolute paths, parent traversal, symlink traversal, protected directories, and known credential filenames. Full-computer mode has no remote workspace and requires explicit absolute file paths and shell working directories. Choose a separate local folder for desktop preview and Git; it never becomes the remote file scope.

G

GIT + PROCESS TOOLS

Inspect local state

Use Git status, staged-only diffs, recent commit subjects, and a process list containing names and PIDs only. Git status, local staging/unstaging, and commits disable configured clean/process filters to avoid running repository commands; files that rely on filter normalization may appear modified in status. Git commits apply to already-staged changes after one-time local diff approval; hooks/signing are disabled and commits never push automatically.

⌕

OPTIONAL · PUBLIC WEB

Search and scrape

The local Web tools toggle starts disabled and needs native confirmation to enable. web_search sends its query to DuckDuckGo; web_scrape fetches one public HTTPS page without cookies or saved credentials. Responses are size/time bounded, private and local network addresses are blocked, and returned page text goes to Arena. Treat it as untrusted content.

⌘

LOCAL REPOSITORY WORKBENCH

Configure and review Git

Initialize at the selected local repository root, inspect change counts, stage or unstage visible files, browse history, and review a full staged diff before a local commit. Disable Git locally to block both this workbench and remote Git tools. A classic or fine-grained GitHub PAT stays in the desktop process; Review & push shows outgoing commits and requires native local confirmation. No force-push, automatic push, or token in the Git URL/config/command line. In full-computer mode, choose a separate local repository for Git and preview. Configure project notes in a bounded local ARENA.md.

Ⅱ

LINK STAYS LIVE

Pause remote control

Temporarily block remote requests other than health checks without changing the URL or pairing key. Pending approvals are cancelled; actions already running may finish. Stop the link or rotate the key to revoke access.

‼

EXTREMELY DANGEROUS

Optional full-computer access

Two native warnings remove the remote file workspace boundary for the next connection. Remote file actions require explicit absolute paths and can expose credentials to Arena.ai; writes still follow Ask or Read only mode. Choose a separate local folder for desktop preview and Git. Combining with No-Ask requires an exact local warning, 30-second lockout, slide-to-unlock, and final confirmation.

◷

REVIEW

Approval queue

Pending file writes, staged Git commits, commands, and changing or unknown Studio calls appear in Arena Local for review. Git commits show their complete staged diff and can only be approved once; other eligible actions can use exact-session approval.

⌘

ROBLOX STUDIO MCP CLIENT

Connect local Studio tools

Arena Local launches Roblox Studio's built-in MCP server over local stdio. Known read-only tools can inspect the selected Studio instance; mutating and unknown tools follow Ask/Read only/No-Ask, and every Studio-targeted call requires an explicit studio_id. Arena Local is not an MCP server.

⇄

CONNECT

Temporary HTTPS link

The local API listens on loopback. ngrok forwards the authenticated API; the desktop UI itself is not served through the public tunnel.

:3

LOADING SCREEN

arena local :3

The launch splash shows the current boot stage, exactly what the agent is asking to do, and the files it is touching — mirrored live from the task queue, straight into the loading screen and a persistent control-center banner.

✦

OPTIONAL · EMBEDDED CHAT

Talk without leaving

The real arena.ai agent is embedded as an in-app panel that loads automatically by default, with a Settings switch for manual loading. Your prompts and sign-in stay between you and Arena; the panel never gives the bridge your Arena credentials, and tool requests still come back for local approval. A bottom-left Settings screen also keeps your profile, custom Arena instructions, appearance, integration toggles, and GitHub-token controls in the local app.

✎

REQUIRED NARRATION

Explains, then edits

The copied setup prompt and the public agent guide both require the agent to say what it is about to change and list the exact files before touching them — and to summarize the files it actually touched when done. No silent changes.

THREE PERMISSION MODES

Choose the gate.

Ask is the default. Modes apply on this computer; the copied prompt also tells the agent to respect the live mode.

DEFAULT

Ask before changes

File reads, Git/process inspection, known read-only Studio tools, and locally enabled Web actions run automatically. File writes, Git commits, shell commands, and mutating or unknown Studio tools wait in the local approval queue until you decide.

RESTRICTIVE

Read only

File reads, Git/process inspection, enabled Web actions, and known read-only Studio tools remain available. Writes, Git commits, shell commands, and other Studio tools are denied, not silently rerouted.

VERY DANGEROUS

No approval

Writes, staged Git commits, commands, and mutating or unknown Studio tools execute immediately. Studio tools can alter open places or run Luau. This is not a sandbox or a shortcut around OS permissions; data loss is possible.

No-approval mode requires two native confirmations. Combining it with full-computer access requires the exact local warning, a 30-second lockout, slide-to-unlock, a final native confirmation, and another warning before starting the link; the remote API cannot enable the combination. Full-computer access is off by default, rotates the key, and resets when the link stops, the key rotates, a connection attempt fails, or the app closes. Changing the separate local folder rotates the key and returns No-Ask to Ask without disabling full-computer scope. Read the full safety model →
